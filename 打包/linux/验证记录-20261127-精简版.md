## 五、踩坑实录（重要，防再犯）

1. **Windows bsdtar 不能打 Linux 包**：从 NTFS 打 tar 会丢执行位与 symlink，
   装出去 python3 打不开——必须 WSL 里 tar（pkg-prepare.sh 的存在理由）。
2. **LX_SYMLINK 与 robocopy 不兼容**：WSL 在 NTFS 上建的 symlink 是 LX reparse
   point，robocopy 报 ERROR 1920 无法复制。仓库副本统一「symlink→文本」形态
   （macos 运行时在 NTFS 上的现状同款），发行时由 pkg-prepare.sh 重建真链接。
3. **`技能/_runtime/linux` 历史污染事故**：该目录 2026-10-20 起被装进过一份
   Windows embeddable（成因未查明的历史烂账），与今天重建的 Linux 布局在同一
   NTFS 目录混居——`lib`（小写，Linux）与 `Lib`（大写，Windows）被 NTFS 大小写
   不敏感合并，pyd/dll 被进程内存映射锁死删不掉。处置：整目录改名隔离
   （`_runtime/linux-烂账-重启后删`，重启后可删）+ 原位纯净重建 + 打包脚本加
   「Windows 残留防呆」（顶层出现 Lib/Scripts/.exe/.pyd/.dll/python* 一律拒绝出包）。
   **连带事故（已修复，留档防再犯）**：装配脚本的 tar 流解压把 Linux `python/`
   解进 `_runtime` 下与 Windows 运行时**同名**的 `python/`（合并解压），随后
   `mv python linux` 在 linux 未删净时把**整个混合目录（含 Windows 5005 个文件）
   搬进 linux/**，再被下一轮 `rm -rf linux` 连带删除——Windows 运行时整目录蒸发
   （正在跑的 3 个 python worker 靠内存映射无感）。已 `git checkout` 从基线完整
   恢复（import PIL/numpy/onnxruntime 实测 OK）。**铁律：装配脚本解压目标名必须
   与既有目录绝对错开**（先解到 `python-临时名/` 再 mv），绝不裸用 `python/`。
4. **PowerShell 5.1 坑**：`-in`/`-match` 大小写不敏感（小写 `lib` 误中 `Lib`
   防呆规则，需 `-ceq`/`-cmatch`）；wsl.exe 把 .wslconfig 警告打到 stderr 会被
   PS 判为 NativeCommandError 中断管道，调用一律 `2>$null` 丢 stderr、失败只认
   退出码与 stdout 标记。
5. **PEP 668**：Ubuntu 24.04 系统 python3 的 pip 拒装（externally-managed），
   兜底路径需识别后带 `--break-system-packages` 重试（skills_linux.go 已处理）。
