# 排查报告：热更新版本升不上去与「无法重启」死循环（2026-11-20）

## 现象（用户口径）

昨天 exe 改名版（20261119-1）之后：安装包路径正常；走热更新后客户端**版本始终停在
20261117-1**，且「没法正常重启」。

## 根因：热更通道上从来没有发过正确的 19 号 engine

两层事实（210 服务器现场取证）：

1. **生产源（2227，全体客户端在用）从未发布过 19 号版**：`/updates/latest` 的
   tag 仍是 20261117-1（11-17 09:05 发），files/ 里没有任何 19 号 engine——
   昨天的改名提交 `c7e10d03` 本地出了安装包，但热更通道没发。
2. **内测源（2228，昨晚 22:22 的测试现场）发了一版「标签与载荷不符」的更新**：
   版本号写着 `20261119-2`，engine 载荷却是 **17 号的旧二进制**
   （engine-20261117-1.zip，sha256 与生产 17-1 逐字符一致）。客户端拿到后：

   ```
   交换 → 重启 → 新进程自报 20261117-1 ≠ pending 的 20261119-2
        → FinalizeEngineSwap 判定「交换被外部覆盖」→ 清账并立即重新检查
        → 又下载同一坏包 → 再交换 → 「待重启」横幅回来 → 无限循环
   ```

   版本永远升不上去、每次重启都像没生效——正是「版本还是 17 号 + 没法正常
   重启」的全部症状。用户猜的「新程序是新名字、旧程序没被替换」不成立：
   新二进制根本没到过客户端。

发布侧为什么会发错：`jxai-server publish-update` 只登记调用方给的文件，不校验
载荷内容；`-engine` 传了旧 zip，版本号却取 `-version`（20261119-2）。

## 修复

### 1. 客户端护栏：engine 载荷版本闸（update_blocks.go）

`applyEngineBlock` 在交换前校验解出的 exe 字节里**真带本版版本串**（版本号经
`-X main.appVersion` 注入为 ASCII 字面量，正常产物必命中；与发布脚本
`发布静默更新.ps1` 的出包自检同一性质）。扫不到＝载荷与版本号不符＝拒装，
回退整包横幅，磁盘上正跑的旧版分毫不动——把「发错载荷」从客户端死循环变成
一条明确报错。`TestVerifyEngineCarriesVersion` 覆盖四分支。

### 2. 旧名 exe 残件自清（update_blocks.go + exe_rename_windows/other.go）

换名迁移后 `FinalizeEngineSwap` 按**新名**前缀扫 `.old/.new` 残件，扫不到
`坚祥数字助理GO.exe.old`（热更换名机器上会永久留着几十 MB 死文件）。自清前缀
名单加入旧名（`legacyExeResiduePrefixes`，非 Windows 为空桩）。

### 3. 重发正确的热更版本（2228 内测源）

- 构建 `20261120-2`（当前 HEAD + 上述护栏；`-ExeBaseName=AI数字助理`，
  发布脚本版本串自检通过：exe 内命中 20261120-2）。
- scp 上 210 → sha256 两端一致 → `publish-update` 发布到 2228：
  blocks.json 现为 `engine.version=20261120-2 / file=engine-20261120-2.zip`，
  回下载 sha256 逐字符一致。坏状态的 20261119-2 被 latest 覆盖；已陷循环的
  测试机下轮检查即拿到好包自愈。

## 端到端验证（隔离实例，本机）

模拟真实老用户：从生产源下载**正版 17-1 旧名二进制**（坚祥数字助理GO.exe），
隔离目录 + 独立 data/技能/组件，更新源指向 2228，浏览器服务形态运行：

| 步骤 | 结果 |
|---|---|
| 启动 30 秒后首查 | ✅ 下载 engine-20261120-2 并完成交换（磁盘换新、旧 exe → .old、enginePending=20261120-2，/api/status 报待重启） |
| POST /api/update/restart | ✅ WMI 接力托管 → 旧进程干净退出（exit 0）→ 接力 5 秒后拉起新版（restart.log 留痕） |
| 新版首次启动 | ✅ 迁移 `20261119.exe-rename` 执行：exe 换名 坚祥数字助理GO.exe → **AI数字助理.exe**；快捷方式/卸载项迁移按设计跳过（隔离目录 ≠ 注册表 InstallLocation） |
| 版本结算 | ✅ 「静默更新已生效：当前版本 20261120-2」；state.json 清空 |
| 残件清理 | ✅ 坚祥数字助理GO.exe.old 被清，目录只剩 AI数字助理.exe |
| 死循环回归 | ✅ 新进程 30 秒后自查：available=false、无再下载、无再交换，进程稳定存活（WMI 拉起、不依赖测试 shell） |

单测：`TestVerifyEngineCarriesVersion`、`TestVersionCompare` 全过；`go build ./...`、
`go vet` 干净。

## 遗留与建议

1. **生产源（2227）发布待拍板**：engine `20261120-2` 已验证可发（发布产物在
   `打包\静默更新\20261120-2\`）。发布后全体 17 号老客户端会在一小时内静默
   升级并自动完成 exe 换名。装包路径（下载页/Gitea 的 20261119-1 安装包）与
   本次改动无关，不受影响。
2. **可选加固（服务端）**：`jxai-server publish-update` 收 `-engine` 时校验包内
   exe 含 `-version` 版本串，把「发错载荷」拦在源头。客户端护栏已兜底，此项
   非必须；需要动服务端仓库与 210 部署，建议另开任务。
3. 本版 engine 为 HEAD 代码（含 11-19/11-20 已提交的语音 1.3.14 引擎侧修复、
   右栏浏览器浮层让位等）；voice 1.3.14 **组件包**未随本版发布（快照沿用
   1.3.13），由语音那条线自行发版。
