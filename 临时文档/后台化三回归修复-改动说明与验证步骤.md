# 后台化改造三个回归修复（计划过程不可见 / 审批后无卡片 / 压缩历史搜不回原文）— 改动说明与验证步骤

> 2026-11-19。对应提交：79c5a0cd24（问题1）、806c0a2e07（问题2）、a374ffd72a（问题3）、c102ed0d38（文档）。
> 关联改造：835111af02（后台回执统一为合成工具回执对 toolreport）与 d85216d5d6（后台等待项挂出即弹卡）。

## 三个问题的根因（隔离实例复现取证）

复现环境：`.jxai/tmp/repro3/`（独立 dataDir + 端口 19201 + 假模型 fakellm.py 剧本状态机，
exe 为当前源码编译的隔离副本，启动 cwd 必须在隔离目录内——config 的 dataDir/workspace 是相对路径）。

### 问题 1（最严重）：计划批准后，执行过程在前端完全不可见
- **根因**：`runtime.go startToolReportRound`（后端拉起的续跑轮）的事件分发只 `run.publish(ev)`
  ——只发本轮订阅者通道。这种轮没有 HTTP 请求挂着 SSE（区别于用户发消息的 handleChat→serveRun），
  前端也没有主动接流，于是执行期间（实测 29 秒、多轮模型调用）**没有任何事件到达前端**；
  跑完后 `done` 广播触发整包拉取，所有中间结果一次性出现。
- 对照：用户消息轮的 `executeRun` emit 里，message 等消息级事件会广播 `session_updated`
  （前端 refreshCurrentSoon → loadSessionInto 发现 running → attachRun 接流 → 实时跟随）。
- 复现证据（修复前）：批准(t0) 后 t0+0.8s 落回执对两条 message（无 SessionID 的裸广播，前端
  message 分支不处理 assistant/tool 行）→ **29 秒事件真空**（DOM rows 恒 8/lastSeq 恒 10）→
  t0+30s done → DOM 一次性跳到 rows 89/lastSeq 172。

### 问题 2：计划审批通过后，前端没有完整的「计划已审批」卡片
- **根因 a（前端）**：`web/app-chat.js` 的 ROW_ITEM_BUILDERS.chat 里，`origin=toolreport` 的行
  被强制按普通工具行折叠（`syn ? 'tool' : …`），exit_plan_mode 回执不升格计划卡——审批完对话区
  只剩一行「exit_plan_mode 参数{"background":true}」折叠行。
- **根因 b（后端）**：`asyncReceiptPair` / `resolvePersistedPlan` 构造回执对时 args 只回显
  `{"background":true}` 不带 plan，即使前端升格，planCardRow 也拿不到计划全文。

### 问题 3：搜索压缩过的历史，搜到的是删减版而不是原文（两个环节）
- **3a（读取层）**：`historytools.go historyRowParts` 对工具调用参数一律按 `argKeepLimit=500`
  折叠——**seq 单条完整读取也截**。实测：643 字参数（独特串在第 600 字后）被规则压缩折叠后，
  `read_session_messages(seq=341)` 返回 554 字且声明「本条共 554 字，已全部显示」——参数只剩
  前 500 字，连 from_char 续读入口都没有。压缩折叠视图承诺的「全文取 read_session_messages(seq=N)」
  兑现不了。**原文一直在库里（compact 列不改 content），前端能显示的原文模型读不回。**
- **3b（搜索层）**：`store.go SearchMessages` 按 `ORDER BY id DESC` 取「会话内最新命中」——
  而模型发起 search_sessions 时查询词本身就写在那条调用的参数里（自引用，永远最新），
  把真正含原文的旧行挤出结果。实测搜独特串命中 seq=826（本次搜索调用自身）而非原文行 174/341。
- 注：3a/3b 并非 11-18 改造引入（折叠与排序都是既有逻辑），但在「压缩后靠 seq 标号找回原文」
  这个新工作流里暴露。

## 改了什么

| 文件 | 改动 |
|---|---|
| runtime.go | executeRun 的内联 emit 提取为 **runEmitOf**（行为不变）；startToolReportRound 改用它，landToolPair 也传入 emit——回执对两条 message、执行轮的每条 message 都广播 session_updated，前端据此接流实时跟随 |
| asyncask.go | asyncReceiptPair 计划分支 args 回显完整识别参数（`{"plan":…,"background":true}`） |

| web/app-chat.js | exit_plan_mode 的 toolreport 回执升格计划卡；planCardRow 头部按回执正文亮「计划已审批（已通过）/未通过/已取消」+ approved 绿边（同步模式批准后同样生效） |
| web/style.css | .pc-badge.ok / .plan-card.approved 绿色（亮暗两主题，暗色 --green 提亮为 #4ac07d） |
