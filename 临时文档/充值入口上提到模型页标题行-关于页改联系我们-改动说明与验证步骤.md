### 三个设计取舍（写清为什么）

1. **插槽留在主程序手里，组件只往里放按钮**：沿用原有通用机制（`prov:render` 事件 + `.pf-card-slot` 挂载点 + `data-cx-owner` 清理），没有新造框架；主程序只多做了一件事——把挂载点从表单挪到标题行。
2. **页签改名只改文本节点**：菜单项与页内标题都是既有元素里的纯文本节点，改成「模型与充值」后元素的 `data-pane`、选中态、窄屏返回头（`set-back-title` 取的就是同一处 `textContent`）全都不受影响；`dispose` 按记录写回原文，**组件关掉一定是「模型」**。找不到「文本正好是模型」的节点就不动（主程序若改结构，这处静默跳过，不硬改也不重建元素，因此不会闪烁）。
3. **二维码白底不跟随主题**：深色主题下深底二维码扫不出来，`.contact-qr` 固定白底 + 浅边框；图片 `max-width: 180px`、等比缩放（实测渲染 180×246）。

### 版本兼容（组件与 exe 各自热更，必须两头都不炸）

- **新 exe + 旧组件 1.0.1**：旧组件 CSS 自带 `.pf-card-slot` 与 `:empty` 规则，旧 JS 的选择器与新挂载点一致 → 按钮照样出现在标题行（只是方形描边样式，等组件更到 1.0.2 变胶囊）。
- **旧 exe + 新组件 1.0.2**：旧挂载点在展开后的表单里，空 `<span>` 无样式不占位；按钮退回「展开才见」，页签改名照常生效（菜单在 `index.html` 里，结构没变）。
