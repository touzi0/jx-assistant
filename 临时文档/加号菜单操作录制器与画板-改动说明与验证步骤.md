# 加号菜单新增「操作录制器」与「画板」- 改动说明与验证步骤

> 2026-11-24 · 前端改动为主（`web/index.html`、`web/app-chat.js`、新增 `web/app-whiteboard.js`、`web/style.css`），后端只改两处文案（`agent.go` 创建技能提示词里的按钮名、`recorder.go` 停录通知措辞）· 构建方式：`go build`（前端经 go:embed 内嵌，替换正在运行的 exe 后生效；`-webdir web` 开发模式下刷新页面即生效）

## 改了什么

### 1. 操作录制器进了加号菜单（创建技能以外的模式也能用）

它以前叫「演示记录」，只在创建技能模式下以权限芯片右侧那枚 ▶/■ 按钮出现。现在：

- 加号菜单多一项「操作录制器」（排在「文件上传」之后）。**点一下是在输入框下方挂出一枚「录制胶囊」**（与「计划」胶囊同族、同一位置）：胶囊里 ▶ 开始录（全局钩子自动截图＋记事件＋录音，与创建技能模式同一套后端 `/api/demo-record/*`）、■ 停止并把材料以【演示记录】通知送进**当前对话**（AI 照常 read INDEX.md / read_image 看操作过程），✕ 把胶囊收起（录制中收起＝先停录收录）。整颗胶囊都是起录/停录键，只有 ✕ 是收起。首页（没开会话）也能录，停止后开个对话即可分析。
- 录制中：胶囊整颗变红、文案变「录制中」、小圆钮换白底红 ■ 呼吸；**所有输入区**（主对话与右栏子对话）都会显示胶囊——停录按钮必须够得着，不管从哪起的录；没挂出过的输入区在停录后自动收起。菜单项红字「● 录制中」；挂出过的输入区菜单项打 ✓。
- 创建技能模式保持原样：专用录制按钮仍在，胶囊与菜单项在该模式下隐藏（按钮在场，不重复）。
- 不支持的平台（非 Windows）胶囊按钮禁用。提示文案统一叫「操作录制器」（按钮 title、提示词里模型对用户说的名字）；材料目录与系统通知仍叫「演示记录」（已有数据与 `isSysNote` 折叠规则不动）。
- 二改说明：一版是录制中给 ➕ 按钮挂一颗红点、起录停录都在菜单项上；按反馈改成上面的胶囊形态（▶/■/✕ 都在胶囊里，像「计划」那样能 ✕ 掉）。

### 1b. 停录材料改为「挂进输入框上方、随下一条消息发出去」（三改，修用户报的两个问题）

用户反馈：① 新建对话页（首页）录的东西没有随上下文发出去；② 停录后看不到任何卡片说明材料放哪了。根因两个：
- 停录只把【演示记录】注记追加到**会话**里（kindReport 行，前端折成一行「上下文材料」）；首页没开会话时无处可落，之后开对话模型一无所知。
- 后端 `demoRecordSession` 还保留着「只在创建技能模式的会话里可用」的守卫：在其他模式的会话里点 ▶/■ 会被 400 拒掉（「演示录制按钮只在「创建技能」模式的会话里可用」），一版的测试全用了桩没打到这条。

改法（按用户的思路：当文件/引用一样挂在输入框上面）：
- `POST /api/demo-record/stop` 不再往会话追加注记行，改为随响应返回 `note`（正文不变：目录、时长、事件/截图数、音频/字幕、下一步 read INDEX.md）。
- 前端 `stageRecord(view, r)`：把材料作为一张**附件卡**挂进停录输入区上方的附件区（kind=record：红点图标 + 「演示记录 record-…」+ 副标「1分33秒 · 12 事件 · 5 张截图」，title 是完整注记，✕ 可移除）。发送时 `flushAttachments` 对它不上传、直接把注记放进「用户附件：」块——与文件附件同一条通路，首页录的跟着懒创建的第一条消息走，会话里录的跟下一条消息走；用户气泡里以灰行显示。toast 改为「录制已收录：材料卡在输入框上方，写一句要 AI 做什么再发送」。
- `demoRecordSession` 去掉模式限制：任何模式的本地会话都能录（远程会话仍拒绝）。
- 提示词（agent.go 两处）与 AGENT.md 同步改成「停录后材料随用户下一条消息的『用户附件：』块到达」。
- 四改（按反馈）：气泡里材料注记占 5 行太长 → 注记改成**单行**（「用户附件：」块本就按行计），气泡里一段录制只占一条灰条、只露前 10 字「【演示记录】用户点停…」，与引用行同款；全文在 title（按句切行，系统提示浮窗可读）；输入框上方的材料卡 title 同样切行。

### 1c. 停录不等语音识别（五改）

用户反馈：首次用语音、录得又长时，点停止要多等一会儿——停录在等语音识别（`recAudioFinish` 等 `asrDone` 上限 8 秒，首次用语音时本地模型要加载，识别必然滞后，这 8 秒纯属白等；超时后 `讲解.srt` 虽然后来还会写出，INDEX.md 却不会更新）。

改法：
- **停录只做停钩子、停采集、写 audio.wav**（实测 30ms 级返回）。识别 worker 继续在后台把在途段转完：`pending` 计数改为「入队 + 识别中，字幕落盘后才减」，停录时 `pending>0` 即 `ASRPending=true`；`recorderCollectASR` 起后台 goroutine 等 `asrDone`，经 `recorderASRDone` 钩子（server.go NewApp 注册）重建 INDEX.md（把字幕并进对照表）并广播 `demo_record_transcribed{output=目录, data:{cues, note}}`。
- 停录响应多了 `asrPending` / `cues`；通知里字幕一句分四种实况：已出 n 段 / **后台识别中**（稍后 read，或用语音组件的识别脚本补转）/ 未生成（同上）/ 无音频。INDEX.md 生成时若还在识别，字幕行同样写「后台识别中」。
- 前端：材料卡副标带「语音转写中…」，toast 说「语音在后台转写，不用等」；收到 `demo_record_transcribed` 时 `updateRecordCards` 把两个输入区里还挂着的同一份卡换成「字幕 n 段」并更新 title 里的注记（已发出去的不动）。`renderAttachments` 的重绘签名加进了 sub/note（否则只改这两个字段不会重画——测出来的）。
- 退出时 `recorderShutdown` 仍等后台识别 ≤8 秒（进程一退 worker 就没了）。
- **字幕没出来时模型怎么办——不进客户端**（用户定的边界：不加模型工具、提示词里不写路径）：一版曾加了 `transcribe_recording` 工具，按反馈整个撤掉（含为它写的补转内核与 WAV 解析）。现在只在停录通知、INDEX.md 与系统提示词（agent.go 两处）里提醒一句：「语音组件里有本地识别脚本，可以自己想办法调 Python 对 audio.wav 重新识别」——模型按环境提示词里的客户端位置自己找脚本。VAD 状态机保留为跨平台的 `recVAD`（recorder.go，采集循环用它），结构比原来散在会话字段里清楚。
- 测试：`TestRecVAD`（合成语音/静音序列切段与时间轴、纯静音不出段、无待定稿内容返回 dropped）、`TestRecorderCollectASRBackground`（Windows：桩住识别卡住 → 停录立即返回且 ASRPending → 放行后钩子带最终段数回调、INDEX 重建；无在途/无识别线/失败段/队列满四种边界）。撤掉工具前曾用语音组件历史听写录音实测过文件重放补转（10.8 秒音频 → 1 段字幕 3.1 秒），证明「模型自己调语音组件脚本识别 audio.wav」这条路本身是通的。

### 2. 画板（新功能，`web/app-whiteboard.js`）

加号菜单「画板」，任何模式、首页 / 主对话 / 右栏子对话都能开：

- 居中弹窗，白底画布（不随暗色主题翻黑），工具条：**画笔 / 文字 / 橡皮**，颜色 **黑、红、蓝、绿、黄 + 自选色**（点那颗四色小圆弹系统取色器），三档线宽（细 / 中 / 粗，文字字号随之 20 / 26 / 34），**撤销（Ctrl+Z）/ 清空**（清空也可撤销）。
- 文字工具：在画布上点一下就地出现输入框，**Enter 落笔、Shift+Enter 换行、Esc 取消**，输入法选字时的 Enter 不会误落笔。
  - 修复（二改）：首版真机点画布出不来输入框——pointerdown 没拦默认动作，随后的 mousedown 默认焦点动作把刚聚焦的输入框立刻失焦、空内容被当成取消收走（合成事件测试没有默认动作，当时没暴露）。现在 pointerdown 一律 `preventDefault`，并对刚打开 150ms 内的失焦重新聚焦兜底；真实鼠标点击 + 真实键入复核通过。
- **「插入到输入框」**：把画布导成 PNG（2000×1240）进**发起它的那个输入框**的附件区——与粘贴图片同一条通路，点发送时作为图片随消息带给 AI（模型用 read_image 看）。插入后画布清空；点「关闭」则保留内容，下次打开接着画。
- 手机端：画布按弹窗可用宽高缩放，手指直接画（touch-action:none 防滚动），返回手势＝关窗，说明文字让位给高度。

## 手工验证步骤

1. 用新编译的 exe 打开（或 `-webdir web` 开发模式刷新页面）。
2. 首页（标准办公）点输入框左下角 ➕：菜单第二、三项应为「画板」「操作录制器」；点「模式」切到「创建技能」再开 ➕：「操作录制器」消失、权限芯片右侧出现 ▶ 按钮；切回「标准办公」它又回来。
3. 点「操作录制器」：权限芯片右侧出现「▶ 操作录制器 ✕」胶囊；点胶囊 ▶ 去电脑上点几下、随口讲两句；回来点胶囊 ■：**应当立刻停**（不再卡等语音识别），**输入框上方出现一张红点「演示记录 record-…」卡**——副标带「语音转写中…」的，等几十秒它自己变成「字幕 n 段」（有 toast 提示），不想等直接发；对话里不再落折叠行。写一句「看看我刚才做了什么」发送：气泡顶部有一条灰色附件行（悬停看全文），AI 去 read INDEX.md 与截图；字幕没出来时 AI 应按提示自己调语音组件的识别脚本补转（没有专门工具）。点 ✕ 胶囊收起。**首页（没开对话）同样试一遍**：停录 → 卡在输入框上方 → 发送后开出的新对话里第一条消息就带着材料说明。
4. 点 ➕ →「画板」：分别用画笔（换几种颜色与粗细）、文字（点一下画布、直接打字、按 Enter）、橡皮画几笔，试撤销 / 清空；点「插入到输入框」：输入框上方出现图片缩略图，发送后 AI 能描述图的内容。关掉画板再打开，上次没插入的内容应还在。
