# 「计划卡一点就卡死」根因与修复 — 报告

时间：2026-11-18 09:0x（编程模式会话，纯前端）
提交：`bf13bcd93c`（`web/app-core.js` 1 行正则 + 注释；另加两个验证脚本）

## 一、根因（一句话）

`web/app-core.js` 里识别文件路径的正则 `FILE_PATH_RE` 是 `(?:[^\s…]*[\\/])+` ——
**分段字符类里也包含了分隔符 `\` 与 `/`**，形成嵌套量词（分隔符既能被 `*` 吃掉、
又能被 `[\\/]` 吃掉），遇到「多段斜杠、结尾没有扩展名」的正文就指数级回溯：
计划里的目录清单（`data/snapshots/2026/11/18/askfold/shots/repro`、
`a/b/c/…/z`）正是这种形态 → 渲染计划全文的那一句 `md()` 就把主线程焊死，
右栏自然画不出来（"打不开"）、整个前端没响应（"一碰就卡死"）。

折叠功能本身没问题：折叠/展开同步耗时 0–0.2ms，DOM 节点数与监听器数在 5 次轮询
刷新后不增长，控制台 0 异常 —— 卡死发生在**点卡片打开计划全文**那一步，也就是
`md(计划正文)` 里。

## 三、改了什么

`web/app-core.js`：`FILE_PATH_RE` 的**第一个字符类**加上 `\\/`（分段字符与分隔符
互斥），并补一段注释说明为什么不能共用字符类。语义不变（同一路径仍匹配同样的
子串，`a//b`、以分隔符开头的路径、盘符前缀都照旧），只是不再回溯爆炸。

上一轮的折叠 UI 与「取消计划」文案**一行没动**；Go 代码、工具定义、接口取值、
`__ignore__` 等提交值全部未改。另一个会话正在改的 `web/app-chat.js` /
`web/style.css`（非阻塞提问那套 `async-plan` / `.pg-ask`）我**没有碰**，

## 六、这个修法还顺带修好的

`md()` 是对话正文、工具结果、计划视图、右栏文件预览共用的渲染器，
而流式输出是逐帧重渲染的。同一份正文里只要出现多段目录路径，以前每帧都可能
卡几百毫秒到几秒（越长的回复越明显）；这次一并消失。

## 七、让改动生效

前端是打包进 exe 的（`go:embed`），用户当前跑的实例读的还是旧前端。两种方式：

- 用现成脚本重编：`编译并启动AI数字助理-开发版.bat`（或 `编译并启动桌面版.bat`）；
- 或者不重编，直接开发模式启动：
  `坚祥数字助理GO.exe -webdir "D:\智能体工作区\软著版数字助理\web"`（改前端后刷新即生效）。
