# 询问/审批卡可折叠成一行 +「忽略计划」改「取消计划」 — 改动说明与验证步骤

时间：2026-11-18（编程模式会话，纯前端）
提交：`5536aa36b4`（`web/app-chat.js` +101/-12、`web/style.css` +31、`web/index.html` +1/-1，
另加验证脚本 `gui-test/ask-fold-verify.mjs`）

背景（用户口径）：计划/权限/提问这三类卡原来钉在输入框上方、高度固定，批复之前
**把刚输出的正文顶上去看不见了**——想先读一遍正文再决定，却没有地方把它收起来。
所以要像右下角那个角标询问框一样有个折叠按钮：一收就只占一行，点一下再展开。
顺带把「忽略计划」这个说法改成「取消计划」（其实它是「本轮停下，计划仍留着」）。

## 改了什么

### 1. 三类卡统一加「折叠成一行」（`askFoldBtn` / `askFoldDecor` / `askSetFolded`）
- 卡片右上角一枚 `—` 按钮（观感对齐右下角角标堆的 `.ask-dock-btn`：短横 + 圆角
  描边），点它把整张卡收成**一行**：`🔐 需要批准 run_command · powershell … 点击展开 ›`；
- 折叠行 = 类型标签（计划待审批 / 需要批准 / 助手提问 / 进入计划模式？）+ 摘要
  （审批 = 工具 · 摘要，计划 = 计划标题，提问 = 问题原文；超长由 CSS 省略号截断，
  全文进 `title`）+「点击展开」+ 右侧箭头；点这一行展开；
- 折叠是**纯视觉**：卡里的输入框/选项/按钮只是 `display:none` 不显示，
  计时、提交、角标/提醒、整卡点击（计划卡点开右栏计划）一概照旧；
- 提问卡的倒计时在折叠行里也留一枚（`.ap-fold .q-count`），折起来也看得见还剩几秒；
- 默认不折叠 —— 没折过的人看到的还是原来的样子。

### 2. 折叠状态按卡片 id 记住（`askFolded`，内存 Set）
- 键 = `a:<审批id>` / `q:<提问id>`；卡片在渲染时按 id 回放这个状态，所以
  轮询/SSE 重绘、内容变了导致的节点重建、切到别的对话再切回来，**都不会弹回展开**；
- 卡片被处理掉（`removeQuestion` / `removeApproval`）时顺手把这条记忆删掉；
- 只存内存（随页面走），不落 localStorage —— 与「折叠段/过程行展开记忆」同一约定。

### 3. 卡片头部结构：右侧成组（`.ap-head-right`）
倒计时 / 停表 / 折叠按钮包进一个靠右的组里。原来倒计时靠 `margin-left:auto` 贴右，
再塞一个 auto 会把空档对半分、倒计时不再贴右——成组后倒计时位置不变，折叠按钮在最后一位。
倒计时刷写从 `querySelector('.q-count')` 改成 `querySelectorAll('.q-count')`
（展开态与折叠行各一枚，`askHoldTimer` 与 `question_deadline` 两处都改）。

### 4. 文案：「忽略计划」→「取消计划」（提交值不动）
- 计划审批卡（`buildQuestionCard` 的 plan 分支）按钮文字 + `title`；
- 右栏「计划」视图底部的同名按钮（`index.html` 的 `#plan-ignore` → `#plan-cancel`，
  `app-chat.js` 里的绑定同步改名）；
- 提交值仍然是 `__ignore__`：**后端语义、接口取值一个字没动**，只是给人看的字改了。

## 逐处文案对照（原文 → 改后）

| 位置 | 原文 | 改后 |
|---|---|---|
| `index.html` 计划视图 `#plan-cancel` 按钮文字 | 忽略计划 | 取消计划 |
| 同上按钮 `title` | 搁置这份计划：本轮对话到此结束（等同点「停止」），计划仍留着，随时可以再批准或修改 | 取消这份计划：本轮对话到此结束（等同点「停止」），计划仍留着，随时可以再批准或修改 |
| `app-chat.js` 计划审批卡按钮文字 | 忽略计划 | 取消计划 |
| 同上按钮 `title` | 搁置这份计划：本轮对话到此结束（等同点「停止」），计划仍留在这里，随时可以再批准或修改 | 取消这份计划：本轮对话到此结束（等同点「停止」），计划仍留在这里，随时可以再批准或修改 |
| `app-chat.js` 计划卡动作注释 | 三个动作：修改（带反馈文本）、忽略计划（本轮就此停下、计划仍留着）、批准执行。 | 三个动作：修改（带反馈文本）、取消计划（本轮就此停下、计划仍留着）、批准执行。 |
| `app-chat.js` `decideQuestion` 注释 | 「忽略计划」= 搁置：… | 「取消计划」= 搁置：…（并补一句「提交值仍是 `__ignore__`」） |

说明：提问卡/审批卡里原本没有「忽略」类文案（审批是 允许/始终允许/拒绝，提问是
发送/拒绝/选项），所以没有第二处「忽略」要改；也没有出现两个「取消」打架的情况
（原来那个表示「放弃输入/关弹窗」的按钮不存在于这三类卡上）。

## 明确没动
- **Go 代码一个字节没改**：`interact.go` 的 `__ignore__` 分支、`/api/questions`、
  `/api/approvals` 的入参与行为原样（验证里确认提交 body 仍是 `{"answer":"__ignore__"}`）。
- 工具定义、卡片的请求/轮询/SSE 契约、`askSigOf` 卡片签名、草稿存取（`askDraft*`）、
  声光提醒、角标堆逻辑都没改。
- 对话流里的「计划卡」（`planCardRow`）不是待批复的询问卡，不加折叠。

## 验证（隔离实例 + headless Edge 真实点击 + 截图对比）

脚本：`gui-test/ask-fold-verify.mjs`（`node gui-test/ask-fold-verify.mjs`，**ALL PASS 16**）。
做法：临时 config + 独立 dataDir/workspace + 独立端口（8846 改动前 / 8847 改动后），
打桩 `/api/approvals`、`/api/questions` 造出 计划/审批/提问 三张卡；「改动前」那份
web 目录是 `git show HEAD:web/...` 取出的 HEAD 版本，同一套桩、同一窗口尺寸量盒模型。

覆盖到的 16 项：
1. 三类卡都有右上角折叠按钮、默认都不折叠；
2. 折叠后三张卡高度都是 34px（一行，折叠行 20px 高）；
3. 折叠后正文**看得见**的高度 131px → 571px（腾出 440px）；
4. 折叠行文案是「类型 + 摘要 + 点击展开 + ›」；提问卡折叠行里倒计时仍在（∞/mm:ss）；
5. 轮询刷新后仍折叠；卡片内容变化导致节点重建后仍折叠（`dataset.fresh=1` 那次）；
6. 切到另一个对话再切回来仍折叠；
7. 展开态：卡片总高、标题行/正文行/输入行/按钮行高度、看得见的高度与改动前**逐项相同**
   （标题行没被新按钮顶高）；全部展开后回到同一组数字；
8. 输入框打字 → 折叠 → 展开，字还在；折叠状态下再来一次刷新重建，字仍在；
9. 计划卡按钮是「取消计划」，`#plan-ignore` 已不存在，`#plan-cancel` 的 onclick 在；
10. 点「取消计划」提交的是 `__ignore__`，卡片不被乐观移除（仍在等处置）；
11. 展开后审批卡「允许」照常提交 `{"approved":true,...}`。

## 留给别人的接口
- 折叠记忆是模块级 `askFolded`（`app-chat.js`「卡片折叠成一行」一节），键由
  `askCardKey(e)` 给；改卡片数据结构不影响这套折叠（折叠只加 `dataset.askkey` 与
  一个 `.ap-fold` 子节点，`.ap-card.folded` 用 CSS 藏其余子节点）。
- 折叠态不进 `askSigOf` 签名，所以不会因为折叠触发整卡重建。
