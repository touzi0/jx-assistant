# 远程访问图片三链路修复（2026-11-20）

## 症状（用户报告）

远程访问（手机 / 外网电脑经网关接入）时：
1. 对话里的图片看不到——工具读取图片（read_image / 浏览器截图 / OCR 框选 / pdf 渲染页）
   的工具卡片图全部裂图；
2. 设置页里的图片看不到（微信二维码、关于页 LOGO）；
3. 「远程访问能看到浏览器截图」从来没正式看到过，一闪而过。

## 根因

远程外壳页挂在外网网关源上，家端的一切都要经 fetch 劫持走加密隧道；`<img src>` 与
静态文件路由都拿不到：

| 症状 | 根因 |
|---|---|
| 工具卡片图 | 附件端点 `/attachments/<hash>.png` **不在隧道白名单**（前端 tunnelPath 与家侧 relayPathAllowed 都只放行 /api/、/sites、/s/）——前端 assetURL 里的 fetch 不被劫持、直接打到网关源 404，退化返回原路径后 `<img>` 再次 404 裂图。「一闪而过」= img 加载占位一闪即裂 |
| 设置页二维码/关于页 LOGO | 外壳拼装（p2pShell）只内联了 CSS/JS/logo/favicon，`/wechat-qr.png`、`/logo-default.png` 仍引用家端静态路由，远程端 404 |
| 右栏浏览器镜像 | 代码通路本身完好（帧走 /api/ 白名单）；「一闪而过」实际是工具截图信封裂图的观感。本次真机式验证帧镜像链路可通（见下） |

## 修复（3 个文件）

| 文件 | 改动 |
|---|---|
| `remoteaccess.go` | `relayPathAllowed` 放行 `/attachments/`（中继与 P2P 直连共用，两条通道同口径）；`p2pShell` 内联 `wechat-qr.png` 与 `logo-default.png`（后者复用已读的 logo.png 字节，brand_sync.go 出的就是同一张）为 dataURL——外壳单文件自包含设计，远程端不再依赖家端静态路由 |
| `web/remote-boot.js` | `tunnelPath` 白名单同步放行 `/attachments/`（与家侧同口径；工具卡片 JX_REMOTE.assetURL 的 fetch 由此进隧道） |
| `remote_images_test.go` | 新增 TestRelayPathAllowedAttachments（含无斜杠/相似前缀拒绝）与 TestP2PShellInlinesStaticImages（外壳无残余静态引用、dataURL 与源文件字节一致、内联 remote-boot 带上白名单） |

安全面：/attachments/ 与 /api/ 同级——只能经已鉴权隧道（中继验 pairKey / 直连 auth 帧）
到达家端回环服务；附件文件名内容寻址（SHA-256）不可枚举，loadAttachment 自带路径穿越校验。

## 验证

单测：`go test -run "TestRelayPathAllowedAttachments|TestP2PShellInlinesStaticImages"` 全过；
`TestBridgeCore*` / `TestDefaultLogoRoute` 回归全过；`go build` 通过。

端到端（真机式，隔离实例 + 210 测试网关 jxaizz.com:2229 + 全新设备号 TOFU 注册，
本机浏览器打开配对页模拟手机远程）：
1. **工具卡片图**：附件库放测试图后，在外壳页里 1:1 复刻 toolRow 渲染路径
   （`JX_REMOTE.assetURL('/attachments/verify/test.png')` → `<img>`）——fetch 经隧道
   返回 200、2775 字节完整，blob URL 上屏 onload，320×180 解码正确；
2. **设置页图片**：`#contact-qr img` src 为 dataURL（301,026 字符）、关于页 LOGO 同为
   dataURL（内联生效）；
3. **右栏浏览器镜像**：家端（会话同 sid）navigate example.com → 外壳页右栏「浏览器」
   视图显示 WebP 帧（1256×761 解码 complete、镜像区可见）；家端换页百度后 3.5 秒内
   远程帧跟随更新。顺带复现一个非 bug 成因：navigate 不带 session（开共享实例）而
   远程轮询带会话号时，显示「电脑端浏览器未打开」——真实场景（AI 在会话内
   browser_open）同一实例，无此错位。

## 遗留说明

- Markdown 正文里的**外链**图片（`![](http://…)`）远程端自行拉取，指向家端内网/
  localhost 的外链仍看不到——外链本身不在家端，属天然限制，不在本次范围。
- 用户发送的图片在**历史消息气泡**里本来就不回显（产品现状，本地远程一致），
  本次未改。
